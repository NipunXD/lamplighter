## Description (copy from here down)

Merchants lose revenue in small, undramatic ways: a UPI request times out, a card hits its daily limit, an AutoPay mandate gets paused, a wholesale invoice drifts past due. Lamplighter is an AI agent that wins that money back — rendered as a cozy town where every customer is a house and every payment at risk is a dark lantern.

Built solo for the Razorpay AI Buildathon 2026, Track 3 (AI Revenue Recovery).

HOW IT WORKS
Rules read Razorpay's structured error first. When they can't tell (a generic payment_failed carrying a raw bank string like "U30: DEBIT HAS BEEN FAILED"), a local Qwen model classifies the root cause under a strict JSON schema. A policy engine then enumerates every possible intervention — silent retry, payment link per channel, Hinglish voice script, a capped incentive, mandate re-auth, escalate, close — and runs every rule against each one. The model only ever chooses among options the policy already approved, and it explains its pick in one line. Message copy is drafted by the model and checked by a validator for the exact amount, the merchant name, an opt-out line and banned language, falling back to a template when it fails. Every outreach creates a real Razorpay test-mode Order behind a self-hosted checkout page, verified by HMAC signature and captured server-side.

THE RULES IT WORKS UNDER
Quiet hours 21:00–09:00 IST. DND registry respected. Three touches maximum, no repeats, a minimum gap between them. Never retry a hard decline. Disputes go to humans only. Incentives capped, budgeted, and never for a funds problem. STOP ends everything, including retries already scheduled. Every extra knock costs goodwill in the expected-value maths.

RESULTS (120 cases, 14 simulated days, same customers for both arms)
Recovered ₹3,41,785 of ₹10,74,826 at risk, against ₹1,36,148 for a naive retry cron. 59 cases recovered against 19. Half the customer touches. 11 complaints against 55. Zero policy violations against 358. Diagnosis accuracy went from 71.7% with rules alone to 100% once the local model reads the bank strings. Across ten different seeded worlds the agent wins 10 of 10 on money and on complaints, with a 95% confidence interval that excludes zero.

WHAT'S REAL AND WHAT'S SIMULATED
Real: Razorpay test-mode Orders, the hosted checkout, HMAC-SHA256 signature verification, payment capture, the local model, the policy engine, the hash-chained audit log. Simulated: the customers, each with a hidden archetype, a salary day, an annoyance threshold and a chance of replying STOP — none of which the agent can see. Payments that would land after the window are not counted. The repo says all of this plainly.

STACK
TypeScript, Node, Express with server-sent events, React and hand-written SVG for the town, Vitest, Razorpay Node SDK in test mode, and Qwen3-4B running locally in LM Studio (no API spend, nothing leaves the machine, and the agent still works with the model switched off).

THE VIDEO ITSELF IS GENERATED BY CODE
No screen recorder and no editor. Playwright drives a scripted stage page that embeds the live app, the narration is neural text-to-speech running locally, and ffmpeg muxes the result. The Razorpay payment you see at 02:22 is a real test-mode transaction completed during the recording. See film/ in the repo.
